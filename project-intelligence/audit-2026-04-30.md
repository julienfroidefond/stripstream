# Audit codebase — 2026-04-30

Audit thorough du projet stripstream (Next.js 16 App Router, TypeScript, Prisma + SQLite, multi-provider Komga / Stripstream Librarian). Objectif : identifier les vraies faiblesses (sécurité, performance, complexité, conflits, SSR) avec impact mesurable.

> Tous les `file:line` réfèrent à l'arbo `src/`. Les éléments déjà fixés au moment de l'audit sont notés "✅ déjà traité".

**Traités** : #4 (KomgaImageService isolé), #5 (tags granulaires), #6 (force-dynamic retiré), #7 (false positive — déjà clean), #8 (authz + rate-limit), #9 (catch loggés), #10 (favorite services mergés), #12 (useImageLoader réduit à 364 l. + bug retry next-book corrigé), gestion d'erreurs provider (status-aware codes, home tolère 1-2 providers down). ## 🔴 Critiques

### 1. Credentials Komga / Stripstream non chiffrés en BDD

- **Fichiers** : `src/lib/services/config-db.service.ts`, `src/app/actions/stripstream-config.ts`
- `KomgaConfig.authHeader` = `Buffer.from("user:password").toString("base64")` → encodage, pas chiffrement
- `StripstreamConfig.token` stocké en clair
- Si `prisma/dev.db` (ou la BDD prod) fuit, toutes les credentials Komga des users sont décodables en 1 ligne
- **Fix** : chiffrer les champs `authHeader` et `token` avec `crypto.subtle` (clé d'env `ENCRYPTION_KEY`). Migration : déchiffrer/rechiffrer l'existant.

### 2. localStorage non scopé par userId (multi-user sur même device)

- **Fichiers** : `src/components/reader/hooks/useReadingDirection.ts:8`, `src/lib/registerSW.ts:19`, `src/hooks/useBookOfflineStatus.ts:36`, plusieurs autres
- Clés globales (`reading-direction`, statuts de download, SW flags) → user A et user B sur la même tablette partagent l'état
- **Fix** : helper centralisé `buildStorageKey(userId, key)` à substituer partout
- ✅ Déjà traité : `client-offlinebook.service.ts` scope par origine de serveur (cf. commit `6abd57a`)

### 3. Aucun test automatisé

- 0 % de couverture sur des hooks critiques :
  - `useImageLoader` (432 lignes — retry, prefetch, abort, eviction)
  - `usePageNavigation` (sync progression, edge cases)
  - Providers (pagination, normalization Komga vs Stripstream)
- Chaque refacto = roulette russe — on l'a déjà vu avec la régression `revalidateTag`
- **Fix incrémental** : Vitest + `useImageLoader.retryImage` + `FavoriteService` cache isolation

## 🟠 Importants

### 4. `ImageService` hardcodé Komga ✅ (commit `ad79b15`)

- **Fichier** : `src/lib/services/image.service.ts:14`
- `ConfigDBService.getConfig()` retourne **toujours** la config Komga active (le service est nommé génériquement mais ne l'est pas)
- Stripstream contourne via routes API custom `/api/stripstream/images/...` → asymétrie d'archi
- **Fix appliqué** : renommé en `KomgaImageService` (sous `src/lib/services/komga/`) → nom = vérité, plus d'asymétrie trompeuse

### 5. Tags de cache trop larges ✅ (commit `7147605`)

- **Fichier** : `src/lib/providers/komga/komga.provider.ts:214,263`
- `SERIES_BOOKS_CACHE_TAG` est un seul tag pour **toutes** les séries → invalider 1 série invalide tout
- Hit rate dégradé inutilement
- **Fix appliqué** : tags granulaires `series-books:${id}`, `library-series:${id}` ajoutés ; `revalidateTag(tag, "max")` ciblé sur mutation

### 6. `force-dynamic` sur les routes images Komga ✅ (commit `7147605`)

- **Fichier** : `src/app/api/komga/images/books/[bookId]/pages/[pageNumber]/route.ts:10`
- Désactive le cache Next.js même si la response renvoie `Cache-Control: max-age=2592000`
- Chaque image = round-trip Komga, alors qu'elles sont immutables côté serveur
- **Fix appliqué** : `force-dynamic` retiré, le `Cache-Control` du handler reprend la main

### 7. `setInterval` sans cleanup dans `DownloadManager` ✅ (faux positif)

- **Fichier** : `src/components/downloads/DownloadManager.tsx:114`
- Pas de `return () => clearInterval(interval)` dans le `useEffect`
- Memory leak + ghost updates si le composant unmount pendant un refresh
- **Vérifié** : `clearInterval` est bien présent (l. 111) — l'audit s'est trompé

### 8. Server actions de test connection sans authz ni rate-limit ✅ (commit `ad79b15`)

- **Fichier** : `src/app/actions/config.ts` (`testKomgaConnection`), `src/app/actions/stripstream-config.ts` (`testStripstreamConnection`)
- Aucun appel à `requireUserId()` → théoriquement brute-forçables (l'attaquant peut tester des combos `(url, user, pwd)` arbitraires depuis n'importe quel client authentifié, voire pas authentifié si la route n'est pas protégée par middleware)
- **Fix appliqué** : `requireUserId()` + `checkRateLimit` (utils/rate-limit.ts) sur les 4 actions test

### 9. `.catch(() => {})` silencieux dans `useReaderState` ✅ (commit `ad79b15`)

- **Fichier** : `src/components/reader/hooks/useReaderState.ts` (effet de prefetch)
- Erreurs de prefetch swallowed → diagnostic impossible en cas de bug réseau
- **Fix appliqué** : `.catch((err) => logger.warn(...))` sur les chaînes concernées

### 10. Deux services Favorite (singulier + pluriel) ✅ (commit `ad79b15`)

- **Fichiers** : `src/lib/services/favorite.service.ts` + `src/lib/services/favorites.service.ts`
- `FavoriteService` (CRUD) et `FavoritesService` (agrégation enrichie via provider) cohabitent → confusion d'import, double source potentielle, naming piégeux
- **Fix appliqué** : `favorites.service.ts` supprimé, API mergée dans `FavoriteService.listFavorites(context?)`

### 11. `Preferences` dédoublé (Context + Service) ⏸️ (analysé, écarté)

- **Fichiers** : `src/contexts/PreferencesContext.tsx` + `src/lib/services/preferences.service.ts`
- Conclusion après analyse : **pas une vraie duplication** — rôles distincts (client cache vs serveur Prisma), `revalidatePath("/", "/libraries", "/series")` déjà présent dans l'action. Le seul vrai grief = sync cross-tab, jugée non prioritaire (option BroadcastChannel disponible si besoin futur).

### 12. `useImageLoader` : 432 lignes, sans tests ✅ (commit `b3abc97`)

- **Fichier** : `src/components/reader/hooks/useImageLoader.ts`
- Concentre : prefetch concurrency, eviction LRU, retry backoff, AbortController, promise tracking
- Pas de tests → impossible de valider la logique de retry / cleanup
- **Fix appliqué** : `prefetchImage` et `prefetchNextBook` partagent un `prefetchKey(key, url)` générique → bug latent corrigé (le prefetch du livre suivant n'avait pas de retry). 432 → 364 lignes. Helper pur `computeEvictionKeys` extrait dans `imageEviction.ts` (testable). Pas d'infra de test installée pour le moment.

## 🟡 Mineurs (à noter)

### 13. Edge cases du reader non gardés

- **Fichier** : `src/components/reader/hooks/usePageNavigation.ts`
- `pages[0]` undefined si page 0, `currentPage > totalPages` non validé, double-page sur la dernière page non clampé
- **Fix** : guards `if (page < 1 || page > totalPages) { logger.warn(...); return; }`

### 14. `key={index}` dans les skeletons

- **Fichiers** : `src/components/skeletons/OptimizedSkeletons.tsx:29,61,83`
- Flicker possible quand la liste réelle arrive et "remplace" les skeletons (React reconcilie mal)
- **Fix** : keys stables (uuid statique, ou `key={\`skel-\${i}\`}` au minimum pour clarifier l'intention)

### 15. `Promise.allSettled` sans logging des rejections

- **Fichier** : `src/app/layout.tsx:88`
- Si un service fail, on retombe sur les valeurs par défaut sans warning → user voit du stale silencieusement
- **Fix** : `if (x.status === "rejected") logger.warn({ err: x.reason }, "...")`

### 16. Triple `connections.find(c => c.isActive)` dans `ConnectionsSettings`

- **Fichier** : `src/components/settings/ConnectionsSettings.tsx:99-101`
- Pattern bizarre, source de bugs futurs lors de copy-paste
- **Fix** : `const active = connections.find(c => c.isActive); const activeKey = active ? \`\${active.type}-\${active.id}\` : undefined`

### 17. `ConfigDBService.getConfig()` mal nommé

- **Fichier** : `src/lib/services/config-db.service.ts`
- Le nom suggère "config courante (générique)" mais retourne uniquement la Komga active
- **Fix** : renommer `getActiveKomgaConfig()` ou refondre en service polymorphe

### 18. Fichiers > 400 lignes

- `useImageLoader.ts` 432, `Sidebar.tsx` ~360+, `stripstream.provider.ts` 418
- **Fix** : extraire des sous-modules / hooks dédiés

### 19. `AbortController` cleanup non garanti dans `useImageLoader`

- **Fichier** : `src/components/reader/hooks/useImageLoader.ts:249`
- `.finally()` peut ne pas être atteint si erreur catastrophique avant
- Memory leak edge-case
- **Fix** : try/catch défensif dans le finally

### 20. `Promise.all` du prefetch sans abort en démontage

- **Fichier** : `src/components/reader/hooks/usePageNavigation.ts`
- Si le composant unmount avant resolve, setState potentiellement called sur un composant démonté → warning React en dev
- **Fix** : `isMountedRef.current` guard ou AbortController
