# A provider registry owns what differs between connection types

ADR [0004](./0004-one-connection-module.md) put every connection path in `src/lib/connections`, and announced that a new provider would extend `resolve`, `manage` and `probe`. In practice the type was re-decided everywhere: about nine `if (provider === "komga")` branches across `resolve.ts`, `manage.ts`, `probe.ts` and `active.ts`, one more in `provider.factory.ts` and `media-transport.ts`, and two server-action files (`config.ts`, `stripstream-config.ts`) exposing six pairs of actions that differed only by their fields (`username`/`password` vs `token`) and by messages that had already drifted. `list*Configs` swallowed every error into `[]`, so a database outage looked like "no connection". On the client, `ConnectionsSettings` and `ProviderSwitcher` each redeclared `UnifiedConnection`, the Komga+Stripstream merge, `keyOf`, `TypeBadge` and the `type === "komga" ? actionKomga : actionStripstream` choice, and they activated a connection differently: the sidebar reloaded the page (a `router.refresh()` can keep RSC segments streamed for the previous cookie), the settings screen only refreshed — the latent bug the sidebar comment described. Adding a third backend meant touching about fourteen existing files.

What varies per provider type is now data in two tables:

- `CONNECTION_DESCRIPTORS` (`src/lib/connections/descriptors.ts`, client-safe): labels, badge classes, placeholders and the input fields with their rule (`always` / `on-create`, trimmed or not). `validateConnectionInput`, `validateConnectionDraft` and `validateConnectionRef` derive the validation from it; the settings form and the server actions run the same code.
- `PROVIDER_DEFINITIONS` (`src/lib/connections/registry.ts`, server): a `ProviderDefinition<P>` per `ProviderType` with its descriptor, `missingConfigCode`, a Prisma `store` (`findOwned`, `findFirst`, `findLabel`, `list`, `create`, `update`, `remove`), `toConnection` (decrypts), `environmentConnection`, `draftConnection` (ad hoc test), `encodeSecret` (encrypts, keeps the stored secret on a blank update), `createProvider` and `loadMediaTransport` (both lazy imports, which also avoids an import cycle with the media transports). The map is typed `{ [P in ProviderType]: ProviderDefinition<P> }`, so a provider without a definition does not compile.

`resolve`, `manage`, `probe`, `active`, `createProvider` and `getMediaTransport` consume a definition chosen by the value's `provider` (`getProviderDefinition`, `definitionFor`). The six action pairs become five generic actions in `src/app/actions/connections.ts` — `listConnections`, `saveConnection(input: ConnectionInput)`, `deleteConnection({ provider, id })`, `activateConnection({ provider, id })`, `testConnection({ stored } | { draft })` — on `runAction` with `requireUser`, `testConnection` adding the runner's `rateLimit` on the existing per-provider key (ADR [0023](./0023-every-action-through-the-runner.md)); the redundant `userId as number` casts disappear with the typed runner context (ADR [0029](./0029-services-receive-the-caller-identity.md)). On the client, `src/lib/connections/client.ts` (`toUnifiedConnections`, `connectionKey`, `connectionSlug`), `ConnectionTypeBadge` and `useActivateConnection` are shared by both components, and the hook alone owns the post-activation full reload. `stripstream.client.ts`, the last pass-through in front of `ProviderTransport` (left over by ADR [0027](./0027-media-addressed-and-cached-by-kind.md)), is removed: the Stripstream provider and `series-identity.ts` take a `ProviderTransport` like Komga does.

## Considered options

- Keep per-provider actions and only share a helper: rejected. The duplicated surface (twelve exports, two message sets) is what drifted; a helper keeps the fork points in every caller and in the client's ternaries.
- Put the descriptor fields on the server definition only: rejected. The form needs the field list and rules without importing Prisma; a client-safe descriptor referenced by the definition keeps one source for both sides.
- A schema library (zod) for the inputs: rejected for now. The rules are two (`always` / `on-create`) plus trimming; the hand-written validator is short, exhaustively tested and adds no dependency.
- Fully generic typing without a cast: rejected. TypeScript cannot correlate a `ResolvedConnection` union with the matching `ProviderDefinition<P>` method; one documented `widen` cast in the registry expresses the invariant ("the definition is always picked by the value's `provider`") instead of a cast at every call site. `validateConnectionInput` likewise builds the union branch with one cast after checking the fields against the provider's descriptor.
- Keep `router.refresh()` after activation in the settings screen: rejected. The active connection is an HTTP-only cookie and the sidebar already documented why only a full reload re-renders every server component with it.

## Consequences

- Adding a provider touches four existing connection files — `ProviderType` (`src/lib/providers/types.ts`), its connection/summary/input types (`connections/types.ts`), one descriptor and one definition — instead of about fourteen (`active`, `resolve`, `manage`, `probe`, the factory, the media-transport factory, two action files, both client components, `ClientSettings`, `SidebarConnections`, the settings page). Its own provider, transport policy, media transport, Prisma table and catalog codes are still needed.
- No `=== "komga"` / `=== "stripstream"` remains in `src/` outside the registry and descriptors, with two documented exceptions: the Komga SQLite favorites fallback in `favorite.service.ts` (ADR [0008](./0008-favorites-store-seam.md)) and Komga's page-index conversion inside its own media transport.
- `listConnections` returns an `ActionResult`: the settings page shows `errors.CONFIG_FETCH_ERROR` instead of an empty list, and the sidebar hides the switcher instead of claiming there is no connection.
- Every failure carries a catalog code (ADR [0014](./0014-error-catalog-completeness.md)): `CONFIG_INVALID_INPUT` and `CONFIG_DUPLICATE_NAME` join the catalog in both locales; a failed probe surfaces the provider's own code (`KOMGA_UNAUTHORIZED`, `STRIPSTREAM_NOT_FOUND`…) because `IMediaProvider.testConnection` now returns it. Success copy moves to `settings.connections.*`; the action `message` is a technical string.
- Activating from the settings screen now reloads the page like the sidebar does; the E2E `data-testid`s (`connection-<provider>-<slug>`, `provider-switch-<provider>-<slug>`) and form ids (`#conn-<field>`) are unchanged.
- The connection cookies keep their names, now derived from the provider (`stripstream-active-<provider>-config`). Without a valid selection, the first config of the first provider in registry order wins, as before.
- *Amended 2026-11-13 by ADR [0032](./0032-closed-by-default-auth-and-per-user-connections.md):* `environmentConnection` is removed from `ProviderDefinition`. No provider has an environment fallback any more; a definition resolves only rows owned by the caller.
- The registry's Prisma calls keep the exact shapes the existing `resolve` / `manage` tests assert; `registry.test.ts` checks every definition is complete (store, catalogued missing-config code, encrypt/decrypt round trip, draft connection, provider construction, media transport).
